## 1. Feedback Strategy Overview

### 1.1 Purpose
Collect structured, actionable feedback from pilot participants to:
- Identify content gaps, inaccuracies, and confusion points
- Validate assessment quality and fairness
- Measure platform usability and technical performance
- Capture "what to remove" — the most valuable feedback for curriculum refinement
- Inform go/no-go decision for full rollout

### 1.2 Feedback Principles

| Principle | Implementation |
|-----------|----------------|
| **Right Time, Right Place** | In-context prompts after lesson/exercise/assessment completion |
| **Minimal Burden** | ≤5 min per touchpoint; ≤15 min for final survey |
| **Actionable Output** | Every question maps to a specific improvement action |
| **Psychological Safety** | Anonymous option; no attribution to performance reviews |
| **Closed Loop** | Feedback → Analysis → Action → Communication back to participants |

### 1.3 Feedback Channels

| Channel | Purpose | Audience | Frequency |
|---------|---------|----------|-----------|
| **In-App Lesson Feedback** | Lesson-level micro-feedback | All participants | After each lesson |
| **Structured Surveys** | Milestone feedback (Foundation, Track, Capstone) | All participants | 3x during pilot |
| **Pilot Feedback API** | Structured pilot programme feedback | All participants | Anytime (optional) |
| **Slack #carbon-academy-pilot** | Real-time discussion, quick questions | All participants + Ops | Continuous |
| **Manager 1:1s** | Qualitative depth | Managers + Direct Reports | Bi-weekly |
| **Support Tickets** | Technical/Content issues | All participants | As needed |

## 4. Feedback Analysis & Action Process

### 4.1 Analysis Workflow

```
Raw Feedback → Categorize → Prioritize → Assign → Fix → Verify → Close Loop
     ↓             ↓           ↓          ↓       ↓        ↓       ↓
  Collect     Tag: Content/   Score:       Assign  Implement  Test    Notify
  Feedback    Platform/      Critical/     to      Fix       Fix     Reporter
   (All src)  Assessment/   High/Med/Low    Owner   (Code/    (QA +   (Close
              Support       /Trivial       (Content/  Content/  Pilot)   Loop)
                            Platform/     Eng/     Support)  Users)
                            Support
```

### 4.2 Categorization Taxonomy

| Category | Sub-Categories | Example |
|----------|----------------|---------|
| **Content** | Accuracy / Clarity / Depth / Relevance / Currency / Structure | "C04.2 Scope 3 mapping example uses outdated emission factors" |
| **Assessment** | Fairness / Clarity / Difficulty / Coverage / Technical | "C08 assessment Q3 has ambiguous wording" |
| **Platform** | Navigation / Performance / Display / Download / Mobile | "Module accordion doesn't expand on mobile Safari" |
| **Exercise** | Clarity / Relevance / Difficulty / Grading / Instructions | "C12.2.3 exercise instructions unclear on breakeven calc" |
| **Support** | Responsiveness / Quality / Availability / Channels | "No response to #training-support after 24 hours" |
| **Logistics** | Workload / Scheduling / Deadlines / Communication | "Week 10 deadline conflicts with quarter-end close" |
| **Curriculum** | Sequencing / Prerequisites / Gaps / Redundancy / Sequencing | "C10 should come before C11 for logical flow" |

### 4.3 Priority Scoring

| Priority | Criteria | SLA | Owner |
|----------|----------|-----|-------|
| **Critical** | Blocks progress for >20% cohort; data loss; security | 2 hours | Platform Eng / Content Lead |
| **High** | Affects >10% cohort; assessment errors; major content error | 24 hours | Content Lead / Assessment Lead |
| **Medium** | Affects <10% cohort; minor content gaps; UX friction | 1 week | Content Lead / Training Eng |
| **Low** | Cosmetic; nice-to-have; single report | Next sprint | Training Ops |

## 6. Closing the Loop

### 6.1 Feedback → Action → Communication

| Step | Action | Owner | Timeline | Communication |
|------|--------|-------|----------|---------------|
| 1 | Feedback received | System | Immediate | Auto-ack to user |
| 2 | Categorize & prioritize | Training Ops | <4 hours | Internal tag |
| 3 | Assign to owner | Training Lead | <24 hours | Slack notification |
| 4 | Investigate & fix | Content/Eng/Support | Per SLA | GitHub PR / Content PR |
| 5 | Verify fix | QA + Training Ops | <48 hours post-fix | Internal test |
| 6 | Deploy | Platform Eng | Next deploy window | Deploy notes |
| 7 | Close loop | Training Ops | <1 week | Email/Slack to reporter + #carbon-academy-pilot announcement |

### 6.2 Communication Templates

**Acknowledgment (Auto):**
> "Thanks for your feedback on [Lesson/Course/Platform]! We've received it and our team will review within 24 hours. You'll hear back when we have an update."

**Resolution (Manual):**
> "Hi [Name], thanks for reporting [issue] on [date]. We've [fixed/clarified/improved] this by [action]. The change is live now. Let us know if it resolves the issue for you!"

**Bulk Update (Weekly):**
> "This week we addressed 12 feedback items: 3 content corrections, 2 assessment fixes, 4 platform tweaks, 3 exercise improvements. Full changelog: [link]. Keep the feedback coming!"

## 7. Feedback Data Management

### 7.1 Data Schema

```sql
-- training_pilot_feedback (existing)
-- training_lesson_feedback (new - micro-feedback)
CREATE TABLE training_lesson_feedback (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  lesson_id UUID REFERENCES training_lessons(id),
  employee_id UUID REFERENCES employees(id),
  rating SMALLINT CHECK (rating IN (-1, 1)), -- thumbs down/up
  issue_tag TEXT, -- 'unclear', 'too_basic', 'too_advanced', 'technical', 'irrelevant'
  comment TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Indexes
CREATE INDEX idx_lesson_feedback_lesson ON training_lesson_feedback(lesson_id);
CREATE INDEX idx_lesson_feedback_employee ON training_lesson_feedback(employee_id);
```

### 7.2 Data Retention

| Data Type | Retention | Disposal |
|-----------|-----------|----------|
| Structured feedback (surveys) | 2 years post-pilot | Anonymize |
| Micro-feedback (thumbs) | 1 year | Delete |
| Open text responses | 2 years | Anonymize |
| NPS scores | 3 years | Aggregate only |
| Competency evidence | 5 years (compliance) | Archive |

### 7.3 Privacy & Anonymity

| Principle | Implementation |
|-----------|----------------|
| **Optional Anonymity** | Checkbox "Submit anonymously" on all surveys |
| **No Attribution in Reviews** | Feedback never linked to performance reviews |
| **Aggregated Reporting** | Minimum 5 responses before showing group results |
| **Data Access** | Training Ops + Content Lead only; no manager access to individual feedback |
| **Right to Delete** | Participants can request deletion via `/api/training/feedback/me` DELETE |

## 8. Feedback-Informed Decisions

### 8.1 Decision Gates

| Decision Point | Required Feedback | Threshold | Action |
|----------------|-------------------|-----------|--------|
| **Content Patch** | ≥3 reports same issue | ≥3 reports same lesson | Content patch within 48h |
| **Assessment Fix** | ≥20% fail same question | p-value <0.05 on discrimination | Assessment patch |
| **Content Removal** | "Remove" > "Keep" in exit survey | >60% vote remove | Deprecate lesson/module |
| **Track Redesign** | Mid-track survey <3.5 avg | <3.5/5 on applicability | Pause track, redesign |
| **Platform Fix** | ≥5 reports same bug | P0/P1 severity | Sprint commitment |

### 8.2 Post-Pilot Content Decisions

| Decision | Evidence Required | Decision Maker |
|----------|-------------------|----------------|
| Keep lesson as-is | Rating ≥4.0, <5% negative tags | Content Lead |
| Revise lesson | Rating 3.0-3.9, specific complaints | Content Lead + SME |
| Remove lesson | Rating <3.0, >60% "remove" votes | Training Lead + HR |
| Merge lessons | Redundancy reported >3x | Content Lead |
| Reorder modules | Sequencing complaints >5 | Training Lead |
| Add lesson | "Missing" theme >20% | Training Lead + SME |
