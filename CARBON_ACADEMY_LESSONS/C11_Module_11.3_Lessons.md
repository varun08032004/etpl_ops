# C11: Credit Quality & Due Diligence
## Module 11.3: Due Diligence Framework (3 lessons × 40min = 2h)

### Lesson 11.3.1: DD Process: Data Room → Score → Memo
**Lesson Code:** C11.3.1
**Duration:** 40 minutes
**Lesson Type:** document
**Tier:** professional

**Learning Objectives:**
1. Execute a structured DD process: data room setup → document review → scoring → investment memo (Bloom: Apply)
2. Build a standardized data room index for carbon credit transactions (Bloom: Create)
3. Write an investment committee-ready DD memo with clear recommendation (Bloom: Create)

**Prerequisites:** C11.2.1, C11.2.2, C11.2.2

**Why This Matters:**
Due diligence is where theory meets practice. A consistent, repeatable DD process ensures no critical risk is missed, enables comparison across opportunities, and produces the documentation needed for investment committee approval, audit trails, and regulatory compliance. This lesson teaches you the end-to-end workflow.

**Core Concept: DD as Evidence-Based Decision Process — Not Checkbox Exercise**

### 11.3.1.1 DD Process Flow — End-to-End

```
PHASE 1: PREPARATION (Days 1-2)
├── 1.1 Define Mandate & Thresholds
│     • Buyer mandate (voluntary/compliance/Art6)
│     • Minimum score, red flag tolerances, budget
├── 1.2 Assemble DD Team
│     • Technical lead, market analyst, legal, finance
├── 1.3 Request Data Room Access
│     • Standard index (see 11.3.1.2)
│     • NDA execution
├── 1.4 Initial Screen (30 min)
│     • Project type, registry, vintage, volume, price
│     • Fatal red flag quick check
       → GO / NO-GO for full DD

PHASE 2: DOCUMENT REVIEW (Days 3-7)
├── 2.1 Technical Review (Technical Lead)
│     • PDD, MR, Verification Reports, VVB credentials
│     • Additionality, Permanence, Quantification deep dive
│     • Red flag register (Module 11.2.2)
├── 2.2 Market Review (Analyst)
│     • Pricing benchmarks, liquidity, comparable trades
│     • Counterparty KYC, settlement terms
│     • Registry/bridge status
├── 2.3 Regulatory/Legal Review (Legal)
│     • Host country authorization, CA status
│     • Contract review (ERPA, term sheet)
│     • Sanctions, export/import compliance
├── 2.4 Financial Review (Finance)
│     • Price vs score, sensitivity, portfolio fit
│     • Cash flow timing, working capital
└── 2.5 Cross-Cutting Synthesis
      • Consolidate red flags across dimensions
      • Score calibration meeting

PHASE 3: SCORING & MEMO (Days 8-10)
├── 3.1 Apply Scoring Framework (Module 11.2.1)
│     • 50-point score with dimension breakdown
│     • Mandate-specific threshold check
├── 3.2 Draft DD Memo
│     • Executive summary + recommendation
│     • Technical, Market, Regulatory, Operational sections
│     • Red flag register with severity & mitigation
│     • Scorecard + comparables
├── 3.3 Internal Review & Challenge
│     • Peer review; devil's advocate
│     • Sensitivity testing (what if carbon price -50%?)
└── 3.4 Final Memo → Investment Committee

PHASE 4: EXECUTION & POST-TRADE (Days 11+)
├── 4.1 Negotiate & Execute (ERPA, SPA)
├── 4.2 Settlement & Registry Transfer
├── 4.3 Post-Trade Monitoring Setup
│     • Ongoing DD triggers (Module 11.3.3)
│     • Portfolio re-score schedule
└── 4.4 Lessons Learned Capture
      • DD process improvement
      • Score calibration update
```

### Lesson 11.3.2: Methodology-Specific DD Checklists
**Lesson Code:** C11.3.2
**Duration:** 40 minutes
**Lesson Type:** document
**Tier:** professional

**Learning Objectives:**
1. Apply methodology-specific DD checklists for major project types (Bloom: Apply)
2. Identify the critical technical risks unique to each methodology category (Bloom: Analyze)
3. Customize the generic DD framework for technology-specific risks (Bloom: Create)

**Prerequisites:** C11.3.1, C08.1.1, C08.2.1

**Why This Matters:**
A solar project and a cookstove project have fundamentally different risk profiles — even if both use Verra and score 40/50. Methodology-specific DD catches the risks that generic checklists miss: suppressed demand baselines for cookstoves, reference region validity for REDD+, grid EF vintage for renewables. This lesson gives you the specialized checklists for the top 10 methodology categories.

**Core Concept: Technology Risk Is Methodology Risk — Customize or Miss It**

### 11.3.2.1 Renewable Energy (Grid-Connected) — VCS AMS-I.D / ACM0002

**Critical Risk Areas & DD Checks:**

| Risk Area | DD Checks | Red Flags |
|-----------|-----------|-----------|
| **Grid Emission Factor** | • Latest CEA vintage used?<br>• Vintage matches verification period?<br>• Conservative (not outdated higher EF)? | • Old EF vintage<br>• EF hardcoded in workbook |
| **Additionality (Investment)** | • Capex benchmark sourced?<br>• Carbon price conservative?<br>• Sensitivity: IRR without carbon < benchmark? | • Carbon price >2x spot<br>• No sensitivity |
| **Metering & Data** | • Revenue meter calibrated?<br>• Check meter exists & calibrated?<br>• SCADA/revenue meter reconciliation? | • Check meter overdue<br>• SCADA gaps > methodology |
| **Leakage** | • Grid import/export monitored?<br>• No material leakage for grid-connected | • Leakage section missing |
| **Vintage & Vintage Split** | • Verification period split at Jan 1?<br>• Correct vintage assignment? | • Wrong vintage on credits |

**AMS-I.D vs ACM0002 Differences:**

| Aspect | AMS-I.D (Small Scale) | ACM0002 (Large Scale) |
|--------|----------------------|----------------------|
| **Capacity Limit** | ≤15 MW | No limit |
| **Additionality** | Simplified (positive list often) | Full investment/barrier test |
| **Monitoring** | Generation only | Generation + grid import/export |
| **Leakage** | Not required | Required (grid import) |

### 11.3.2.2 Wind Power — Specific Risks

| Unique Risk | DD Check |
|-------------|----------|
| **Plant Load Factor (PLF) Assumptions** | Compare PDD PLF vs actual vs regional average |
| **Curtailment Risk** | Grid curtailment history; compensation mechanism |
| **Wake Effects** | Layout optimization; downstream turbine impact |
| **Seasonal Generation** | Monthly profile matches PPA/revenue model |
| **Repowering/Decommissioning** | End-of-life plan; blade waste liability |

### 11.3.2.2 Energy Efficiency / Cookstoves — GS TPDDTEC / VCS AMS-II.G

**Critical Risk Areas & DD Checks:**

| Risk Area | DD Checks | Red Flags |
|-----------|-----------|-----------|
| **Suppressed Demand Baseline** | • Baseline fuel use justified?<br>• Not overstated (suppressed demand cap)?<br>• Survey methodology robust? | • Baseline > national average<br>• No survey; default only |
| **Usage Monitoring** | • Usage rate monitored (not just distribution)?<br>• Method: survey / sensor / hybrid?<br>• Frequency per methodology? | • Distribution = usage assumed<br>• Usage <90% (simplified approach) |
| **Stove Performance** | • Lab-tested efficiency vs field?<br>• Degradation over time modeled? | • Only lab data; no field validation |
| **Leakage (Market)** | • Non-project stove displacement assessed?<br>• Market leakage default applied? | • Market leakage ignored |
| **Non-Permanence** | • Stove replacement rate modeled?<br>• Buffer pool adequacy? | • No buffer; high replacement risk |

**Suppressed Demand Cap Check:**
```
IF Baseline Fuel Use > Suppressed Demand Cap (Methodology):
    → RED FLAG: Baseline overstated → Over-issuance
    
TYPICAL CAPS:
- Rural residential: 1.5-2.0x national average
- Urban: 1.2-1.5x national average
- Check methodology for exact cap
```

### 11.3.2.3 Forestry / REDD+ — VCS VM0033 / VM0007 / GS ARR

**Critical Risk Areas & DD Checks:**

| Risk Area | DD Checks | Red Flags |
|-----------|-----------|-----------|
| **Reference Region Validity** | • Same biome, agents, drivers?<br>• Statistical similarity (proxy testing)?<br>• No leakage into reference region? | • Reference region dissimilar<br>• Deforestation drivers differ |
| **Baseline Deforestation Rate** | • Historical period appropriate?<br>• Trend vs average?<br>• Policy changes accounted? | • Cherry-picked period<br>• Ignores new roads/policy |
| **Carbon Stocks** | • Field plots sufficient?<br>• All pools included (AGB, BGB, soil, litter)?<br>• Conservative stock estimates? | • Default stocks only<br>• Soil carbon omitted |
| **Permanence / Buffer** | • Buffer % ≥ methodology minimum?<br>• Actuarial buffer sizing?<br>• Reversal risk quantified? | • Buffer < minimum<br>• No monitoring plan |
| **Leakage Belt** | • Belt defined & monitored?<br>• Activity shifting vs market leakage?<br>• Quantification conservative? | • Belt not monitored<br>• Market leakage default only |
| **Community / FPIC** | • FPIC documented & ongoing?<br>• Benefit sharing equitable?<br>• Grievance mechanism functional? | • FPIC = 1 meeting<br>• No benefit sharing agreement |

**REDD+ vs ARR (Afforestation/Reforestation):**

| Aspect | REDD+ (Avoided Deforestation) | ARR (Planting) |
|--------|------------------------------|----------------|
| **Baseline** | Historical deforestation rate | Business-as-usual land use |
| **Permanence Risk** | High (external drivers) | Medium (management) |
| **Additionality** | Policy/enforcement barriers | Financial/land use barriers |
| **Leakage** | Critical (activity shifting) | Lower (but market leakage) |

### 11.3.2.4 Industrial Gas / Waste — VCS AM0001 / AM0042 / ACM0001

**Critical Risk Areas:**

| Project Type | Unique DD Checks |
|--------------|------------------|
| **HFC-23 Destruction** | • Plant not built for CDM?<br>• Byproduct ratio monitored?<br>• No perverse incentive (more production = more credits)? |
| **N2O Abatement** | • Baseline N2O rate verified?<br>• Abatement technology additional?<br>• Monitoring continuous (not periodic)? |
| **Landfill Gas** | • Gas collection efficiency measured?<br>• Oxidation factor conservative?<br>• Waste composition representative? |
| **Coal Mine Methane** | • Mine operational status?<br>• Gas drainage vs ventilation?<br>• Regulatory surplus (mandatory capture)? |

### 11.3.2.5 Blue Carbon / Mangroves — VM0033 / GS Mangroves

**Critical Risk Areas:**

| Risk Area | DD Checks |
|-----------|-----------|
| **Sea Level Rise** | • Project area elevation vs SLR projections<br>• Migration pathway secured? |
| **Carbon Stocks (Soil Dominant)** | • Soil cores to sufficient depth (1m+)?<br>• Bulk density measured?<br>• Allochthonous vs autochthonous carbon? |
| **Hydrology** | • Tidal regime natural/restored?<br>• Upstream diversions assessed? |
| **Tenure & Jurisdiction** | • Seabed/foreshore rights clear?<br>• Multiple agency permits? |

### Lesson 11.3.3: Post-Trade Monitoring & Ongoing DD
**Lesson Code:** C11.3.3
**Duration:** 40 minutes
**Lesson Type:** document
**Tier:** professional

**Learning Objectives:**
1. Design a post-trade monitoring system: triggers, re-scoring, alerts (Bloom: Create)
2. Build a portfolio risk dashboard with early warning indicators (Bloom: Create)
3. Implement regulatory change monitoring for credit eligibility (Bloom: Create)

**Prerequisites:** C11.3.1, C11.3.2

**Why This Matters:**
Buying credits is not the end — it's the beginning of a holding period where risks evolve: verification reports arrive, methodologies update, regulations shift, registries freeze. Post-trade monitoring transforms a one-time DD into a living risk management system that protects your portfolio and your claims.

**Core Concept: DD Doesn't End at Closing — It Enters Maintenance Mode**

### 11.3.3.1 Post-Trade Monitoring Architecture

**Monitoring Layers:**
| Layer | Scope | Frequency | Automation |
|-------|-------|-----------|------------|
| **Credit-Level** | Individual credit health | Real-time (webhook) | High (API) |
| **Project-Level** | Project health, verification cycle | Per verification | Semi-auto |
| **Portfolio-Level** | Concentration, quality, liquidity | Daily | Automated |
| **Regulatory** | Policy, standard, registry changes | Real-time (feed) | High (RSS/API) |

**Monitoring Stack:**
```
┌─────────────────────────────────────────────────────────────┐
│                    ALERTING & NOTIFICATION                    │
│  (Slack/Email/PagerDuty — by severity)                       │
├─────────────────────────────────────────────────────────────┤
│                    POLICY ENGINE                              │
│  • Claim rules (vintage, CCP%, abatement)                   │
│  • Concentration limits (project, vintage, registry)         │
│  • Quality floors (score, CCP%, removal %)                   │
├─────────────────────────────────────────────────────────────┤
│                    POLICY ENGINE                              │
│  • Claim rules (vintage, CCP%, abatement)                   │
│  • Concentration limits (project, vintage, registry)         │
│  • Quality floors (score, CCP%, removal %)                   │
├─────────────────────────────────────────────────────────────┤
│                    DATA INGESTION LAYER                       │
│  • Registry APIs (Verra, GS, ICMS, CDM)                      │
│  • Exchange feeds (Xpansiv, CBL, ACX)                        │
│  • Standard body feeds (Verra, GS, BEE, ICAO)               │
│  • Regulatory feeds (BEE, UNFCCC, ICAO, SEBI)               │
│  • News/social (GDELT, regulatory feeds)                    │
└─────────────────────────────────────────────────────────────┘
```

### 11.3.3.1 Post-Trade Monitoring Triggers — Event-Driven Re-Scoring

**Event-Driven Triggers:**
| Event | Trigger Source | Action | SLA |
|----------|---------------|--------|-----|
| **New Verification Report** | Registry webhook / email | Re-score technical dims | < 5 business days |
| **Methodology Update** | Standard body feed | Re-assess baseline/additionality | Before next issuance |
| **Regulatory Change** | BEE/UNFCCC/ICAO feeds | Re-assess regulatory score | < 5 business days |
| **VVB Change** | Registry/VVB notice | Re-assess VVB quality | Immediate |
| **New Verification Report** | Registry webhook | Full technical re-score | < 10 business days |
| **Market Event** | Exchange feed | Re-assess liquidity/price | Same day |
| **Buffer Draw (AFOLU)** | Registry notification | Re-assess permanence | Immediate |
| **Annual** | Calendar | Full portfolio re-score | Annual (Q1) |

**Re-Scoring Workflow:**
```
1. TRIGGER DETECTED
    ↓
2. FETCH LATEST DATA (MR, VR, Registry, Market)
    ↓
3. RE-RUN SCORING ENGINE (Module 11.2.1)
    ↓
3. COMPARE: Old Score vs New Score
    ↓
4. IF DELTA > THRESHOLD (e.g., >5 pts):
      → ALERT → REVIEW → ADJUST PORTFOLIO
    ↓
5. LOG: Score history, trigger, delta, action taken
```

### 11.3.3.1 Early Warning System — Leading Indicators

**Leading Indicator Dashboard:**
| Indicator | Source | Frequency | Alert Threshold | Action |
|-----------|--------|-----------|-----------------|--------|
| **EF Vintage Age** | EF Library | Monthly | > 2 years old | Flag for update |
| **Vintage Age** | Portfolio | Monthly | > 5 yrs avg age | Plan vintage rotation |

| **VVB Findings** | Verification reports | Per verification | New CAR/CL | Re-score |

| **Market Volume** | Exchange data | Weekly | Volume < 10% avg | Liquidity review |

**Alert Escalation:**
| Alert Level | Criteria | Escalation To | Response Time |
|--------------|----------|---------------|---------------|
| **INFO** | Single metric breach | Portfolio Manager | 24 hrs |
| **WARNING** | 2+ metrics or portfolio impact > 1% | Risk Manager | 4 hrs |
| **CRITICAL** | Portfolio risk limit breach | CRO / Investment Committee | 1 hr |
| **EMERGENCY** | Systemic risk (registry freeze, regulatory ban) | CEO / Board | Immediate |

### 11.3.3.2 Portfolio Stress Testing

**Stress Scenarios (Run Quarterly):**
| Scenario | Shock | Portfolio Impact | Mitigation |
|------------|-------|------------------|------------|
| **Carbon Price Crash** | -50% spot price | Revenue impact; margin calls | Hedging; diversification |
| **CORSIA Phase 2 Restrictions** | 50% credits ineligible | Compliance shortfall | Diversify standards |

### 11.3.3.2 Professional Judgement Points
- **Re-score proactively:** Don't wait for verification cycle; trigger on signals
- **Correlation matters:** Solar credits across regions may correlate (weather, policy)

- **Buffer management:** Monitor AFOLU buffer health quarterly
