# C09: Validation & Verification
## Module 9.2: Verification Process (3 lessons × 40min = 2h)

### Lesson 9.2.1: Verification Fundamentals — Scope, Standards & Process
**Lesson Code:** C09.2.1
**Duration:** 40 minutes
**Lesson Type:** document
**Tier:** professional

**Learning Objectives:**
1. Distinguish verification from validation and their distinct roles in the carbon credit lifecycle (Bloom: Understand)
2. Navigate the verification process: planning, site visit, findings, closure, opinion (Bloom: Understand)
3. Apply verification standards: ISO 14064-3, ISAE 3000, ISO 14065, standard-specific rules (Bloom: Apply)

**Prerequisites:** C09.1.1, C03.2.1, C03.2.2

**Why This Matters:**
Verification is the recurring gatekeeper that determines whether credits get issued. Unlike validation (once), verification happens every monitoring period. Understanding the verification process, standards, and VVB dynamics lets you navigate this recurring gate efficiently.

**Core Concept: Verification = Ex-Post Audit of Monitoring Data vs Ex-Ante Validation**

### 9.2.1.1 Verification vs Validation — The Fundamental Distinction

| Aspect | **Validation (Ex-Ante)** | **Verification (Ex-Post)** |
|--------|--------------------------|---------------------------|
| **Question** | "Can this project work as designed?" | "Did this project work as monitored?" |
| **Timing** | Before registration (once) | After each monitoring period (recurring) |
| **Focus** | PDD, methodology applicability, baseline, additionality, monitoring plan | Monitoring report, actual data, ER calculation, compliance |
| **Standard** | ISO 14064-3, ISAE 3000, ISO 14065 | ISO 14064-3, ISAE 3000, ISAE 3410 |
| **Output** | Validation opinion + report | Verification opinion + report |
| **Frequency** | Once (at registration) | Every monitoring period (annual typically) |

### 9.2.1.2 Verification Standards Framework

| Standard | Scope | Key Requirements |
|----------|-------|------------------|
| **ISO 14064-3** | GHG verification | Competence, independence, risk-based approach |
| **ISAE 3000 (Revised)** | Assurance engagements | Ethical, quality control, evidence |
| **ISO 14064-1** | Inventory spec | Verification alignment |
| **GHG Protocol** | Corporate standard | Verification guidance |
| **ISAE 3410** | GHG specific | GHG-specific assertions |
| **ISAE 3410** | GHG assurance | GHG-specific assertions |

**Verification Standards by Program:**
| Program | Verification Standard | Key Requirements |
|---------|----------------------|------------------|
| **VCS** | ISO 14064-3 + VCS Standard | VVB accredited per ISO 14065 |
| **Gold Standard** | ISO 14064-3 + GS Requirements | GS-accredited VVB |
| **CDM** | CDM Validation & Verification Standard | CDM DOE |
| **CCTS** | ISO 14064-3 + BEE Rules | BEE-empaneled verifier |
| **CORSIA** | ICAO CORSIA Verification | ICAO-approved verifier |
| **Article 6.4** | Decision 3/CMA.3 | SB-accredited DOE |

### 9.2.1.2 Verification Process — End-to-End

| Phase | Timeline | Activities | Deliverables |
|-------|----------|------------|--------------|
| **1. Planning** | -8 to -4 weeks | Scoping, team selection, risk assessment, materiality | Verification plan, sampling plan |
| **2. Strategic Analysis** | -4 to -2 weeks | Understand business, boundary, methods, risks | Risk assessment, materiality map |
| **3. Fieldwork** | -2 to +2 weeks | Site visits, data testing, recalculation, interviews | Working papers, findings log |
| **4. Reporting** | +2 to +4 weeks | Draft opinion, management letter, closure | Verification opinion, findings report |
| **5. Closure** | +4 to +6 weeks | Findings closure, final opinion | Final opinion, verification statement |

**Materiality Thresholds (Typical):**
| Level | Threshold |
|-------|-----------|
| **Quantitative** | 5% of total emissions (Scope 1+2); 10% (Scope 3) |
| **Qualitative** | Any misstatement affecting user decisions |

### 9.2.1.3 Verification Sampling — Risk-Based

**Sampling Approach:**
| Population | Sampling Method | Typical Coverage |
|-----------|-----------------|------------------|
| **Facilities** | Risk-based (size, complexity, risk) | 30-50% of sites, 100% of >10% emitters |
| **Emission Sources** | Stratified by magnitude | 100% of >5% sources |
| **Data Points** | Random + judgmental | 25-50 per category |
| **Calculations** | 100% recalculation of sample | 100% of sampled calcs |
| **EFs** | Source verification | 100% of primary EFs |

**Sample Documentation:** Verifier must document rationale, not just results.

### 9.2.1.4 Common Verification Findings — Top 10

| # | Finding | Root Cause | Prevention |
|-----|----------|------------|------------|
| 1 | **Incomplete boundary** | Excluded facilities/categories without rationale | Screening matrix + exclusion register |
| 2 | **EF version mismatch** | Used AR4 EF in AR6 inventory | EF version control |
| 3 | **Missing uncertainty** | No uncertainty quantification | Uncertainty budget template |
| 4 | **Allocation errors** | Arbitrary allocation for shared services | Allocation method register |
| 5 | **Double counting** | Same source in Scope 1 & 3 | Cross-category reconciliation |
| 6 | **Base year not recalculated** | Acquisition not reflected | Recalculation trigger checklist |
| 7 | **Scope 3 category gaps** | Categories excluded without rationale | Screening matrix |
| 8 | **Data trail gaps** | Source docs not linked | Document management system |
| 8 | **EF version drift** | Different EF versions across years | EF version control |
| 10 | **Target-inventory mismatch** | Target boundary ≠ inventory boundary | Target-inventory mapping |

### 9.2.1.5 Verification Readiness Package — Checklist

- [ ] Methodology sheets per category
- [ ] Source document repository (linked to calcs)
- [ ] Calculation workbooks (versioned, reproducible)

### 9.2.1.6 Managing Findings — Closure Process

| Finding Severity | Response Time | Closure Required |
|------------------|---------------|------------------|
| **Critical** (material misstatement) | Immediate | Before opinion |
| **Major** (systemic issue) | 2 weeks | Before opinion |
| **Minor** (isolated, immaterial) | 4 weeks | Before final report |
| **Observation** (improvement) | 8 weeks | Next cycle |

**Finding Response Template:**
1. **Root Cause Analysis** (5 Whys)
2. **Corrective Action** (specific, measurable, owner, deadline)
3. **Preventive Action** (systemic fix)
4. **Verification of Fix** (evidence)
5. **Closure Confirmation** (verifier sign-off)

| Regulation | Verification Requirement | Verifier |
|-----------|-------------------------|----------|
| **SEBI BRSR** | Reasonable assurance (Top 1000) | NABET accredited |
| **CCTS** | Accredited verifier (BEE empaneled) | BEE-approved |
| **CORSIA** | ICAO-approved verifier | ICAO list |
| **CDP** | Third-party verification (Leadership) | ISAE 3000/ISO 14064-3 |
| **SBTi** | Reasonable assurance for target | ISO 14064-3 |

**BEE Empaneled Verifiers (2024):** DNV, BV, SGS, TÜV, IRCLASS, Intertek, LRQA, EY, KPMG, PwC (subject to NABET)

**EtherTrack Context:** Platform generates verification-ready package: inventory report, methodology sheets, source doc links, calculation traceability, uncertainty budget, DQI table.

### 9.2.1.6 Common Verification Failures
1. **Scope 3 sampling too small** → verifier expands scope → cost/time overrun
2. **No uncertainty budget** → limited assurance only
3. **Source documents not in English** → translation delays
4. **Key personnel unavailable** → timeline slippage
5. **Prior year findings unclosed** → escalation to major

### 9.2.1.6 Professional Judgement Points
- **Limited vs Reasonable:** If budget allows, always choose Reasonable — credibility premium
- **Verifier rotation:** Rotate every 3-5 years (independence)
- **Pre-assessment:** Internal mock verification 4 weeks before — catches 80% of findings
- **Multi-year contract:** Locks verifier, reduces ramp-up, but monitor independence

### Lesson 9.2.2: Verification Deep Dive — Fieldwork, Findings & Opinion
**Lesson Code:** C09.2.2
**Duration:** 40 minutes
**Lesson Type:** document
**Tier:** professional

**Learning Objectives:**
1. Execute the fieldwork phase: site visits, data testing, recalculation, interviews (Bloom: Apply)
2. Analyze and respond to verification findings: root cause, corrective action, closure (Bloom: Analyze)
3. Manage the opinion process: reasonable vs limited assurance, opinion language (Bloom: Evaluate)

**Prerequisites:** C09.2.1

**Why This Matters:**
Fieldwork is where verification succeeds or fails. The findings resolution process determines whether you get a clean opinion or a qualified one. This lesson teaches you to execute fieldwork efficiently and manage findings to closure.

**Core Concept: Fieldwork = Evidence Gathering; Findings = Risk Resolution**

### 9.2.2.1 Fieldwork — Site Visits, Data Testing, Recalculation

**Fieldwork Activities:**
| Activity | Scope | Typical Duration |
|-----------|-------|------------------|
| **Site Visits** | Physical inspection, meter checks, interviews | 1-3 days per site |
| **Data Testing** | Recalculation of sample calcs, source doc verification | 2-5 days |
| **Source Document Review** | Invoices, meter reads, lab reports, permits | 2-3 days |
| **Interviews** | Operators, managers, data custodians, community | 30-60 min each |
| **Observation** | Meter reading, sampling, calibration check | 1-2 hours per site |

**Fieldwork Planning — Risk-Based Approach:**
| Risk Factor | High Priority | Standard |
|-------------|---------------|----------|
| **Emission Magnitude** | >10% of total | <5% |
| **Complexity** | Complex process, multiple EFs | Simple combustion |
| **Prior Findings** | Prior major/minor findings | Clean history |
| **Data Quality** | Estimated/extrapolated data | Metered, primary data |
| **Regulatory** | Compliance-critical (CCTS, CORSIA) | Voluntary only |

**Fieldwork Execution Checklist:**
- [ ] Site visit schedule confirmed with client
- [ ] Sampling plan approved by lead verifier
- [ ] Data request sent 2 weeks prior
- [ ] Interviewees confirmed (operators, managers, community)
- [ ] Site access / security clearances arranged
- [ ] Sampling equipment calibrated (if applicable)
- [ ] Verification team briefed on project risks
- [ ] Communication protocol established (daily debriefs)

### 9.2.2.2 Data Testing & Recalculation — The Core of Verification

**Recalculation Requirements:**
| Item | Verification Requirement | Typical Coverage |
|------|--------------------------|------------------|
| **Activity Data** | Trace to source (meter, invoice, log) | 100% of sampled |
| **Emission Factors** | Source verification, version, applicability | 100% of EFs used |
| **Calculations** | Full recalculation | 100% of sampled calcs |
| **Aggregation** | Category → scope → total | 100% |
| **Uncertainty** | Propagation method, inputs | All categories |

**Recalculation Sampling:**
| Population | Sampling Method | Minimum Coverage |
|-----------|-----------------|------------------|
| **Emission Sources** | Stratified by magnitude | 100% of >5% sources |
| **Facilities** | Risk-based | 30-50% of sites |
| **Months/Periods** | Judgmental + random | 3-6 months |
| **Parameters** | All key parameters | 100% |

**Recalculation Tools:**
- Independent spreadsheet (no client formulas)
- Source document → input → calculation → output trace
- Version control (which workbook version verified)

### 9.2.2.2 Common Verification Findings — Fieldwork Phase

| Finding | Typical Cause | Resolution |
|---------|---------------|------------|
| **Source doc missing** | Invoice/meter read not retrievable | Retrieve or estimate with uncertainty |
| **Calculation error** | Formula error, unit mismatch | Correct formula; re-run all |
| **EF version mismatch** | AR4 EF used in AR6 inventory | Update EF; recalc all vintages |
| **Double counting** | Same source in S1 & S3 | Remove from one category |
| **Missing uncertainty** | No uncertainty budget | Develop uncertainty budget |
| **Allocation error** | Arbitrary allocation for shared services | Documented allocation method |
| **Data gap** | Missing months of meter data | Interpolate + uncertainty; flag |

### 9.2.2.3 Findings Management — Root Cause to Closure

**Finding Classification:**
| Severity | Definition | Response Time | Closure |
|----------|------------|---------------|---------|
| **Critical** | Material misstatement | Immediate | Before opinion |
| **Major** | Systemic issue, > materiality | 2 weeks | Before opinion |
| **Minor** | Isolated, immaterial | 4 weeks | Before final report |
| **Observation** | Improvement opportunity | 8 weeks | Next cycle |

**Finding Response Template:**
```markdown
## Finding Response: [Finding ID]

**Root Cause Analysis (5 Whys):**
1. Why did this happen? 
2. Why was that the cause?
3. ...
5. Root cause: [Statement]

**Corrective Action:**
- Action: [Specific, measurable]
- Owner: [Name/Role]
- Deadline: [Date]
- Evidence of completion: [What will verifier see]

**Preventive Action:**
- Systemic fix: [Process change, control, automation]
- Owner: [Name/Role]
- Deadline: [Date]

**Verification of Fix:**
- Evidence: [Document, screenshot, test result]
- Verifier sign-off: [Name, Date]
```

**Closure Confirmation:**
- Verifier reviews evidence → Closes or re-issues
- All Major/Minor must close before opinion
- Observations can remain open to next cycle

### 9.2.2.3 Verification Opinion — Reasonable vs Limited Assurance

| Aspect | **Limited Assurance** | **Reasonable Assurance** |
|--------|----------------------|-------------------------|
| **Conclusion** | "Nothing has come to our attention..." | "In our opinion, fairly stated..." |
| **Work Performed** | Analytical procedures, inquiry | Detailed testing, sampling, recalc |
| **Risk** | Higher (lower confidence) | Lower (high confidence) |
| **Cost/Time** | Lower | 2-3× higher |
| **Conclusion** | Negative | Positive |

**Opinion Language (Reasonable Assurance):**
> "In our opinion, the GHG assertion for [entity] for the period [date] is fairly stated, in all material respects, in accordance with [GHG Protocol / ISO 14064-1 / ISO 14064-3]."

**Opinion Language (Limited Assurance):**
> "Based on our work, nothing has come to our attention that causes us to believe that the GHG assertion for [entity] for the period [date] is not fairly stated, in all material respects, in accordance with [standard]."

### 9.2.2.4 Professional Judgement Points

### Lesson 9.2.3: Verification for Compliance Markets — CORSIA, CCTS, Article 6
**Lesson Code:** C09.2.3
**Duration:** 40 minutes
**Lesson Type:** document
**Tier:** professional

**Learning Objectives:**
1. Apply CORSIA verification requirements: eligible units, vintage, registry (Bloom: Apply)
2. Apply CCTS verification: BEE-empaneled verifiers, CCC issuance (Bloom: Apply)
3. Apply Article 6 verification: corresponding adjustments, ITMO tracking (Bloom: Apply)

**Prerequisites:** C09.2.1, C03.2.3, C03.2.2

**Why This Matters:**
Compliance markets (CORSIA, CCTS, Article 6) have stricter verification requirements than voluntary markets — specific eligible units, vintage rules, corresponding adjustments, and registry rules. A verification that passes voluntary standards may fail compliance verification. This lesson teaches you the compliance-specific verification rules.

**Core Concept: Compliance Verification = Voluntary Verification + Regulatory Overlay**

### 9.2.3.1 CORSIA Verification — Aviation Compliance

**CORSIA Verification Requirements:**
| Element | Requirement |
|---------|-------------|
| **Verifier** | ICAO-approved verifier (list on ICAO website) |
| **Eligible Units** | CORSIA-eligible programs (CDM post-2015, VCS, GS, ACR, ART) |
| **Vintage** | 2016-2020 (Pilot); 2021-2023 (Phase 1); 2024-2026 (Phase 2) |
| **Cancellation** | Units cancelled in CORSIA registry (not retired) |
| **Registry** | ICAO CORSIA Registry (or designated national registry) |
| **Corresponding Adjustment** | Not required for CORSIA (host country adjustment optional) |

**CORSIA Verification Process:**
```
1. Airline submits Emissions Report (ER) to State
2. State engages ICAO-approved verifier
3. Verifier verifies ER against CORSIA MRV
4. Verifier issues Verification Report
5. State submits Verification Report to ICAO
6. ICAO reconciles; issues compliance determination
```

**CORSIA Verification Scope:**
| Element | Verification Focus |
|---------|-------------------|
| **Emissions Report** | Fuel use, EF, emissions calculation, monitoring plan |
| **Monitoring Plan** | Approved by State; consistent with CORSIA MRV |
| **Fuel Use Data** | Fuel receipts, tanker receipts, fuel density, NCV |
| **Emission Factors** | ICAO default or actual (if approved) |
| **Data Gaps** | Approved gap-filling methods only |
| **CORSIA Eligible Units** | Verified cancelled in CORSIA registry |

**CORSIA Vintage Eligibility (Key):**
| Phase | Period | Eligible Vintages |
|-------|--------|-------------------|
| **Pilot** | 2021-2023 | 2016-2020 |
| **Phase 1** | 2024-2026 | 2021-2023 |
| **Phase 2** | 2027-2035 | TBD (post-2023) |

### 9.2.3.2 CCTS Verification — India's Compliance Market

**CCTS Verification Requirements:**
| Element | Requirement |
|---------|-------------|
| **Verifier** | BEE-empaneled verifier (NABET accredited) |
| **Eligible Credits** | CCCs issued under CCTS |
| **Registry** | IEX/PXIL CCC registry |
| **Verification Frequency** | Quarterly monitoring; annual verification |
| **Reporting** | Quarterly monitoring reports to BEE |

**CCTS Verification Process:**
```
1. Obligated entity submits quarterly monitoring report
2. BEE assigns empaneled verifier
3. Verifier verifies monitoring data against CCTS methodology
4. Verifier issues verification report
5. BEE reviews; issues CCCs for verified reductions
6. CCCs credited to entity account on IEX/PXIL
```

**CCTS Verification Specifics:**
| Element | CCTS Specifics |
|---------|----------------|
| **Verifier Pool** | BEE-empaneled only (DNV, BV, SGS, TÜV, IRCLASS, etc.) |
| **Methodology** | BEE-approved CCTS methodologies only |
| **Baseline** | CCTS baseline (may differ from VCS/GS) |
| **CCC Format** | `CCC-YYYY-NNNNNNNN` |
| **Settlement** | T+1 on IEX/PXIL; T+0 bilateral |
| **Banking** | CCCs bankable for future compliance |

**CCTS vs Voluntary Verification:**
| Aspect | Voluntary (VCS/GS) | CCTS Compliance |
|--------|-------------------|-----------------|
| **Verifier** | Any accredited VVB | BEE-empaneled only |
| **Standard** | VCS/GS methodology | BEE-approved methodology |
| **Registry** | Verra/GS registry | IEX/PXIL CCC registry |
| **Unit** | VCU/GS-VER | CCC |
| **Cancellation** | Retirement | Cancellation (compliance) |

### 9.2.3.2 Article 6 Verification — Corresponding Adjustments & ITMOs

**Article 6.2 Verification — ITMO Verification:**
| Element | Verification Focus |
|---------|-------------------|
| **Authorization** | Host Party LoA (format, signatory, scope, vintage) |
| **ITMO Characteristics** | Serial, vintage, sector, mitigation type, host Party |
| **Corresponding Adjustment** | Seller: NDC - ITMO; Buyer: NDC + ITMO |
| **First Transfer** | Registry records first international transfer |
| **Corresponding Adjustment** | Automatic at first transfer (host Party registry) |
| **Reporting** | Annual ETF report with ITMO tracking |
| **Registry** | National registry → Article 6 International Transaction Log |

**Article 6.4 Verification — A6.4ER:**
| Element | Verification Focus |
|---------|-------------------|
| **Supervisory Body** | Activity registered with Art 6.4 SB |
| **DOE** | SB-accredited DOE (not standard VVB) |
| **A6.4ER** | Serial, vintage, host Party, methodology |
| **OMGE** | 2% cancellation for Overall Mitigation in Global Emissions |
| **Share of Proceeds** | 5% for Adaptation Fund |
| **CDM Transition** | Eligible CDM activities may transition |

### 9.2.3.3 Corresponding Adjustments — Verification Mechanics

**CA Implementation Checklist:**
```markdown
✅ Host Party Authorization (LoA) on file
✅ First International Transfer identified
✅ Selling Party: NDC tracking minus ITMO
✅ Buying Party: NDC tracking plus ITMO
✅ Registry sync: National → Article 6 International Transaction Log
✅ CA reflected in next Biennial Transparency Report (BTR)
```

**CA Verification Checklist for Verifiers:**
- [ ] Authorization letter on file (LoA)
- [ ] First transfer identified in registry
- [ ] CA applied to selling Party NDC tracking
- [ ] CA applied to buying Party NDC tracking
- [ ] Transaction logged in Article 6 International Transaction Log
- [ ] CA reflected in next BTR

### 9.2.3.3 Professional Judgement Points
- **CORSIA vintage is absolute:** 2021 vintage cannot be used for Phase 1 (2024-26)
- **CCTS verifier = BEE-empaneled only** — standard VVB not accepted
- **Article 6 CA is mandatory** — no CA = no ITMO transfer
- **Article 6.4 DOE ≠ VVB** — SB-accredited DOE required
- **OMGE = 2% cancellation** — automatic at issuance for A6.4ERs
