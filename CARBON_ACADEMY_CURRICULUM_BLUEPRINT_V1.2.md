### Trigger-Based Review Mechanism
**In addition to scheduled reviews, immediate impact assessment must occur when:**
- BEE publishes a material CCTS change
- Government/Gazette notification changes applicable carbon regulation
- CERC or relevant Indian market rules materially change
- Article 6 rules/guidance materially change
- Registry rules or methodology versions change
- Registry issuance/retirement procedures change
- Exchange trading rules change
- EtherTrack production workflow materially changes
- A critical platform/security architecture change occurs

**Process:**
Change detected → Impact assessment → Content classification → Affected courses identified → Version increment → Assessment review → Refresher/re-certification decision → Employee notification/assignment

## K. CONTENT VERSIONING POLICY

### Change Classification
| Change Type | Trigger | Action Required | ERP Action |
|-------------|---------|-----------------|------------|
| **Minor Revision** | Typo, formatting, link fix | Update lesson; version++; no assessment change | Auto-publish |
| **Major Revision** | Updated methodology, new standard, significant content rewrite | Version++; assessment review; notify assigned employees | Publish + notification |
| **Mandatory Refresher** | Regulatory change (CCTS, Article 6), methodology retirement, major platform change | Version++; new assessment required; mandatory for certified employees | Assign refresher module; deadline 30 days |
| **Re-certification Required** | Competency framework change, new certification level, major architecture change | New version; full assessment cycle; new capstone if structural | Full re-assessment cycle |

### Version Format
`MAJOR.MINOR.PATCH` (e.g., `3.2.1` = 3rd major curriculum, 2nd minor revision, 1st patch)

### Historical Preservation
- All prior versions archived in `training_content_versions` table
- Employee completion records reference exact version completed
- Certificates display version at issuance
- No historical completion lost on content update
